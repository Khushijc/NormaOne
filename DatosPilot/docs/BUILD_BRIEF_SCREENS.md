# Screen build brief (for contributors)

Project root: `DatosPilot/frontend`. Stack: Vite 6, React 19, TypeScript strict (noUnusedLocals), react-router-dom 7, lucide-react, Vitest 4. Dev server already running on **http://localhost:3003** (do not start another, do not run `npm install`, do not touch git).

DatosPilot = **PRL y Documentación**: coordination and evidence management for workplace safety (Spain, SMEs). It is NOT a professional risk-assessment engine, NOT a clinical system and NEVER claims legal compliance or that a workplace is safe.

## Hard rules

1. **No Python** anywhere, not even as a shell helper. Edit files with the Edit/Write tools; Node only for throw-away read-only checks in the scratchpad.
2. **Do not change** `src/domain/**`, `src/services/**`, `src/store/**`, `src/data/**`, `src/components/**`, `src/layout/**`, `src/App.tsx`. They are shared and tested (`src/acceptance.test.ts`, 24 scenarios). If you need a service change or find a bug, describe it in your final report (file, function, problem, proposed fix) instead of editing. You may add small pure helpers or local components inside your own page folder.
3. **All business actions go through the services** (`src/services/*`), never by editing the store. Show success toasts only from the service result: `const { run, runOk, pending } = useAction()` from `components/ui` (`run(() => service(...), 'Mensaje')` shows the error toast with details automatically on failure). Never show success for something that did not happen.
4. **Permissions at component level too.** `const ctx = useCtx()` (`ctx.can(perm)`, `ctx.employee`, `ctx.roles`, `ctx.today`, `ctx.db`, `ctx.company`, `ctx.user`). Hide or disable actions the user may not perform; the service re-checks. Use scope helpers from `services/context`: `visibleEmployeeIds`, `canSeeEmployee`, `visibleWorksiteIds`, `canSeeHealth`, `canReviewAuthority`, `canSeeDocument`, `itemsFor(ctx, employeeId)` (requirement matrix, health masked), `visibleReadiness(ctx)`, `readinessOf(ctx, emp, ws)`, `readinessAggregate(ctx)`, `employeeName`, `userName`, `worksiteName`, `roleName`, `alertDays(ctx)`.
5. **Language and claims.** Never write "cumple", "compliant", "certificado", "seguro". Readiness = «Listo según los requisitos configurados» and always next to `<ReadinessDisclaimer />` where readiness is summarised. Accepted evidence ≠ professional safety approval. Acknowledgement ≠ training. Attendance ≠ completion ≠ evidence acceptance. Upload ≠ approval ≠ receipt by the recipient. A missing date is shown as «No establecida» / «Sin caducidad» / «Revisión necesaria», never invented. Health: show nothing clinical; users without health permission only ever see the masked item (`itemsFor` already masks).
6. **Dates**: three kinds kept apart — legal expiry (`legalExpiryDate`, with `expiryMode` none/date/unknown), provider review (`providerReviewDate`) and internal follow-up (`internalFollowUpDate`). Use `<KindDate kind="legal|provider|internal|target|assessment" date={…} noExpiry={…} today={ctx.today} />` from `components/bits`. `formatDate`, `formatInstant` from `domain/time` for others; `DateText`/`DateTimeText` from ui.
7. **Spanish-first UI with English translation.** Every user-visible string is Spanish source text wrapped in `t()` from `src/i18n` (`t('Hola {name}', { name })`). Module-level constants: `tKey('…')` then render `t(x)`. Domain messages (`Msg` = `{text, params}`, e.g. `item.reason`, readiness reasons, exception reasons) render with `msg(m)` from `components/bits`. Labels from `domain/status` (ITEM_STATUS, READINESS, DOC_STATUS, VERSION_STATUS, ACTION_STATUS, …) are Spanish → render `t(meta.label)` or use the badge components. Add an English entry for every new key to **your own** dictionary part file `src/i18n/en/<part>.ts` (British English, sentence case). Before adding, grep `src/i18n/en/*.ts`: if the key already exists reuse it (a test fails on conflicting translations). Never pass a template literal with `${}` to `t()`. Do NOT add keys for domain/service texts (another contributor owns `domain.ts`, `shell.ts`, `reference.ts`).
8. **States**: every list needs `EmptyState`; forms need inline validation + service error toast; decisive actions need `ConfirmDialog` (`requireReason`) or a `Modal` with the reason field the service requires. Tables: `usePaged` + `Pagination`, sorting `useSort`/`SortHeader`/`sortRows`, search/filters in a `.toolbar`. Loading: services are async (simulated latency) → disable buttons with `pending`.
9. **Styles**: reuse `src/styles/app.css` classes (`card`, `kpis`/`kpi`, `table-wrap`/`table`, `toolbar`, `badge`, `callout`, `grid-2/3`, `grid-main-side`, `stack`, `row`, `row-wrap`, `timeline`, `tabs`, `kv`, `empty`, `muted`, `small`, `tiny`, `strong`, `nowrap`). New CSS only in your own `src/styles/areas/<area>.css` using CSS variables (light + dark). Must work at **375 px** without horizontal page scroll (tables scroll inside `.table-wrap`). Restrained enterprise look: no gradients, no oversized rounded cards, no illustrations.
10. **Accessibility**: labelled inputs (`TextField`, `SelectField`, `TextAreaField`, `Checkbox`), buttons with text or `aria-label`, status never by colour alone (badges have icon + text), charts with table alternative (`StackedBars`, `GroupedBarChart` in `components/charts`).
11. Reference patterns (read-only): `../../JornadaPulse/frontend/src/pages/` (e.g. `team/EmployeeDetailPage.tsx`, `ExceptionsPage.tsx`, `DashboardPage.tsx`).
